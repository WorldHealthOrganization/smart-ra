title
Revise the criteria for designating DPI-H components
requirements
- Define 'foundational health system functions' more precisely, e.g. with a dependency or irreplaceability test - Remove or reword 'non-transactional' so high-volume infrastructural services (consent, registries) are not excluded - Reword 'without modification to core design' to allow configuration, content and localisation while the core stays stable - Reword the non-transactional requirement so it does not exclude legitimate shared transactional infrastructure - Treat recurrence across goals as one criterion among several - Express the intended distinction as not owning point-of-service or programme-specific transaction processing - Define stability as predictable, versioned evolution of purpose and interfaces - Clarify whether public governance is a present or target condition

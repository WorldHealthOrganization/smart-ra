title
Define conformance assessment dimensions, evidence and results
requirements
- Avoid an undifferentiated coverage percentage as the principal adoption measure; report by layer, capability and criticality - Replace the 'left implicit' verdict with an explicit, persistent assessment-result model - Tie 'correctly realises' to normative requirements, test assertions and accepted evidence - Report structural, semantic, behavioural, security and interface conformance separately - Break 'conformance of the architecture' into model validity, reference alignment, coverage, traceability and documented deviation, with expected evidence - Add objectively checkable governance criteria (designated operator, multi-year plan, published performance, transfer plan, dispute route) - Report mandatory/critical failures separately rather than averaging them away - Specify minimum fields: status values, scope, assessor/mechanism, specification and version, evidence, date, validity

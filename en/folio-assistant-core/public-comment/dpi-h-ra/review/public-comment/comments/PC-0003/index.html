The draft is deliberate about versioning at the source. Requirement 3 requires the Terminology Service to "maintain full version history of code systems, supporting concurrent active versions, defined lifecycle states (draft, active, deprecated, retired), and consumer-specified version requests", and explains the choice: "DPI-H elevates this to Required where OpenHIE treats it as a Recommendation; versioning is essential for a governance-grade national terminology service to honour backwards compatibility obligations" (p.167). Requirement 8 does the same for value sets, and the summary of departures from OpenHIE confirms it (p.170, L147–151). What is not stated is what version and temporal context a consuming system must retain with coded data when interpretation is version-dependent. A service able to reconstruct every release does not help a historical clinical record that carries a bare code, and therefore does not identify which meaning, which value-set membership, which display or which mapping applied when the record was created. The record side of the draft shows how close it already is. The Lifelong Health Record must "record and version all updates to clinical data; records shall never be deleted, only marked as such; no previous version of a record shall be overwritten; all prior versions shall remain retrievable" (requirement 3, SHRF-7, p.159, Required). That is immutability of the record. It is not immutability of the record's interpretation: every prior version of the entry is retrievable, and the requirement does not ensure that any of them carries, or can resolve, the code-system version, expansion or map that governed its meaning when it was written. An effective date alone would not close this. Publication time, the period during which an artefact is approved for use, the version a consumer actually applied, and the time a notification was delivered are four different facts, and reconstructing a past interpretation needs more than one of them. The service can already do the work. Requirement 13 obliges the Terminology Service to "expand value sets into the explicit list of concepts they contain at a given point in time, accounting for the version of the underlying code systems and the expansion parameters supplied by the consumer" (p.169, Required). Reconstructing a past reading is therefore an available operation – but only to a caller who still holds the parameters it needs, and nothing requires the record to retain them.
